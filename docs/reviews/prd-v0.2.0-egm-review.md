## 요약

v0.2.0은 v0.1.0의 Blocker 6건을 대부분 해소했다. 해소된 항목은 다음과 같다.

- 선택 상태를 유일한 결정 기준으로 정했다.
- 되돌리기와 삭제를 분리했다.
- 유효 글리프와 오류 음절의 cmap 제외 규칙을 정했다.
- TTF 최소 구성과 메타데이터를 정했다.
- 인수 대상 외부 프로그램을 정했다.
- 용어집, 태그 규칙, GOAL ID, 위험 표, 테스트 시나리오를 추가했다.

새로 추가한 즉석 조합 / 전체 생성 이중 경로와 Undo 우선 흐름에서 새 모순이 생겼다. 구현에 들어가려면 먼저 아래 세 가지를 하나로 정해야 한다.

1. **`GeneratedGlyph`의 정체**
   - FR-04는 이것을 저장된 스냅샷으로 다룬다. "최신 아님"(stale), 원자적 교체, "현재 저장된 결과로 내보내기"가 모두 이 전제에 기댄다.
   - §5는 "저장하지 않는 캐시일 수 있다"고 한다.
   - 8명 중 8명이 이 모순을 지적했다.
2. **커스텀 글리프 보호 규칙**
   - POL-01은 시스템이 커스텀 글리프를 "교체"하지 못하게 한다.
   - 그런데 상태 전이 표에는 다음 세 경로가 있다.
     - 다시 그리기로 교체한다.
     - 보존 중인 커스텀이 있는 상태에서 새로 그려 덮어쓴다.
     - 처음 저장한 커스텀을 Undo해서 삭제한다.
   - 이 셋은 POL-01의 예외 목록에 없다.
3. **Undo와 확인 단계**
   - "저장하면 메모로 돌아간다"와 "편집 화면을 벗어나면 Undo 기록이 사라진다"가 함께 있다. 따라서 "저장 직후 편집 화면 안에서 Undo"는 일어날 수 없다.
   - 상태 표와 TS-05는 `[확정]`인데, 같은 내용을 OQ-06에 미뤄 두었다.

그다음으로 우선할 것은 다음 네 가지다.

- 최신 아님과 재검토 필요를 무엇으로 판정할지 정한다. 의존 집합, 버전, 규칙 업데이트를 포함한다.
- 전체 생성을 한 번도 하지 않은 상태에서 내보낼 때의 동작을 정한다.
- IME 조합 중에 나타나는 호환 자모를 어떻게 표시할지 정한다.
- 폰트 버전 증가와 TS-03의 충돌을 고친다.

## 우선순위별 발견 사항 (Blocker → Major → Nit)

### Blocker

#### B-01. `GeneratedGlyph`를 저장하는지, 캐시인지 서로 다르게 적혀 있음 — 심각도: Blocker
* **리뷰어 관점:** 8명 전원 (`structural`, `comprehension`, `implementation-readiness`, `design`, `zoom-out`, `style`, `inventive-catalyst`, `codebase-details`)
* **영향 범위:** 35, 41–42, 159, 164, 168, 185, 259, 289–290, 297, 320행. TS 33
* **문제:**
  - 다음 문장들은 모두 결과가 영속 저장된다는 전제에서만 성립한다.
    - FR-04(159행): "11,172자 `GeneratedGlyph`로 저장".
    - 168행: 중단되면 이전 결과가 남는다.
    - 164행: 최신 아님 판정.
    - 259행: 현재 저장된 결과로 내보낸다.
    - POL-07(320행): 저장된 전체 생성 결과는 바꾸지 않는다.
  - §5(297행)는 "저장하지 않고 필요할 때 다시 계산하는 캐시일 수 있다"고 한다. 다시 계산하는 캐시라면 최신 아님 상태가 생길 수 없다.
  - 즉 서로 양립할 수 없는 두 아키텍처가 모두 허용된다.
  - 185행 "`generated`이면 자동 생성 글리프를 쓴다"는 앱 안 표시에도 적용된다. 그런데 앱 안 표시는 실제로 즉석 조합 결과를 쓴다(289행). 이 문장만으로는 앱 화면이 저장된 `GeneratedGlyph`를 쓰는지 알 수 없다.
  - FR-01의 저장·복원 목록(114, 121행)과 TS 33에는 전체 생성 결과와 폰트 메타데이터가 빠져 있다.
* **권고:**
  - 297행을 다음으로 바꾼다. "`GeneratedGlyph`는 전체 생성 결과의 영속 스냅샷이며, 다음 전체 생성이 완료될 때까지 바뀌지 않는다. 즉석 조합 결과는 별도의 비영속 캐시다(`CompositionCache`)."
  - 185행을 다음으로 바꾼다. "선택이 `generated`이면 앱 안 표시는 즉석 조합 결과를, 내보내기는 저장된 `GeneratedGlyph`를 쓴다."
  - 114, 121행과 TS 33의 저장 대상에 "전체 생성 결과, 폰트 메타데이터"를 추가한다.
  - 결정 범위 안의 단순화 대안(`zoom-out`, `inventive-catalyst`): "전체 생성"을 내보내기의 내부 단계로 합친다. 즉 내보낼 때 즉석 조합 함수로 11,172자를 계산하고 저장하지 않는다.
    - 이 방식에서도 전체 생성은 사용자가 실행하는 동작으로 남는다.
    - 최신 아님 상태, TS-06, TS-11, 259행의 "TTF가 앱 표시와 다를 수 있음" 안내를 없앨 수 있다.
    - 대신 내보내기 시간(NFR-02의 M)이 길어진다.
    - 어느 쪽으로 정하든 한쪽으로 확정해야 한다.

#### B-02. POL-01의 "교체 금지"와 상태 전이 표, FR-05가 충돌함 — 심각도: Blocker
* **리뷰어 관점:** `design`, `structural`, `comprehension`, `style`, `inventive-catalyst`

  - 240행 `[확정]`은 "조합 중인 음절도 사용자 폰트로 표시"한다고 한다. 그런데 호환 자모 글리프는 `[제안]`이고 TTF에만 해당한다(261행). 242행 규칙대로라면 시스템 폰트로 대체 표시된다. 따라서 확정 요구사항을 지킬 수 없다.
  - `U+3131`~`U+3163`은 51자이고 겹받침(ㄳ, ㄺ, ㅄ…)과 겹모음(ㅘ, ㅢ…)을 포함한다. 위치별 변형인 기본 글리프만으로는 단독 자모의 전체 크기 형태를 바로 얻을 수 없다.
  - 호환 자모는 음절 단위인 `GlyphSelection`/`CustomGlyph` 모델 밖에 있다. 그래서 커스텀 글리프를 만들 수도, 최신 아님을 추적할 수도 없다.
* **권고:**
  - FR-07에 추가한다. "`[확정]` 앱 안 표시는 한글 호환 자모(`U+3131`~`U+3163`)를 기본 글리프로 단독 배치 규칙에 따라 조합해 사용자 글리프로 그린다. 겹자모는 구성 자모 조합 또는 별도 기본 글리프로 만들며, 방식은 OQ-01에서 정한다."

## 잘 된 점 (유지 권장)

- 선택 상태를 유일한 결정 기준으로 둔 것, 불변식, 상태 전이 표는 v0.1.0 Blocker를 깔끔하게 해소했다. 남은 문제는 표의 몇 행과 POL-01의 문구를 맞추는 일이다.
